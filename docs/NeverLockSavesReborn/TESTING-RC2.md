# RC2 testing handoff

October 24, 2026 (America/Los_Angeles). **Build: 1.0.0-rc2.**

The latest uploaded compiler log reports `UNRESOLVED_TYPE` for `AutoSaveSystem` in
the deferred-dispatch variable declaration. RC1 source contains that declaration.
RC2 changes it to the verified `gameAutoSaveSystem` type. The remaining dispatch
behavior is preserved. The reported failure takes precedence over broad working
feedback when assessing release readiness; RC2 is not yet compiled in the user's
game environment by this workflow.

## First: confirm the compile and launch

1. Close the game, retain settings/save/installation backups and install complete
   RC2 `bin/` and `r6/` trees as one Reborn copy. Keep the same dependency/mod setup
   for this first retest; no dependency change or Dark Future installation is
   required by this correction.
2. Launch and inspect fresh REDscript and CET logs generated by that launch.
   Confirm successful compilation, absence of the reported unresolved-type error
   and Reborn's `1.0.0-rc2` identification. Record the package checksum.
3. If the launch still fails, provide the new first compiler error and the relevant
   fresh log. Do not treat the corrected source line or an offline check as an
   actual native compilation pass.

## Then: record actual behavior

After a successful launch, use disposable backed-up game data and distinguish:

| Stage | Observation to record |
|---|---|
| Request/queue | Source/mode/options, blocked or queued state and intended native/intro guards |
| Submission | One checkpoint request after the existing eligibility/stability checks |
| Actual save | A newly created usable save entry, independently of the submission message |
| Reload | Successful loading of that save with expected position/inventory/objectives |
| Progression | Continued gameplay and the relevant quest/objective progression |

Exercise the affected deferred path with manual and automatic queue settings
actually used. Retain the existing cancellation, priority, serial/native recheck,
expiry and dry-run no-save expectations. Record all four modes, optional-mod and
other cases only to the extent actually exercised. Keep unexercised rows untested.

Export local `support-report.json` from the CET overlay and review it before
sharing. Record actual game/framework versions, the installed checksum and
enabled optional integrations; manually fill versions the report cannot measure.
Screenshot labels alone do not establish a complete tested environment.

The read-only RC2 installation auditor under `tools/NLSRInstallAudit/` can check
the 16 installed file identities. Exact bytes and zero log-marker counts cannot
substitute for fresh compile/launch or save/reload/progression results.

## Preserve evidence and scope

The matrix retains the previous 42 case rows and their statuses and adds the
reported RC1-declaration compiler failure as a historical record. A source fix
does not pass the 38 unrecorded gameplay cases. Record already-completed results;
repeat only checks affected by this correction or a newly observed failure.

The optional closed-game Windows companion still needs actual copy/retention/
reactivation, confirmed separate restore and restored-game reload/progression
results if exercised. Hash verification alone does not prove game loadability.
Automatic identity, all-owned-safehouse coverage, live backup/correlated completion
and dependent in-game completion notifications remain deferred after 1.0.

Public publication is paused while the user arranges upstream permission. The
